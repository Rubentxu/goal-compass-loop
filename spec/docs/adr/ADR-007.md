# ADR-007 · Supervisión ACP mínima y efectos aislados (ACCEPTED para diseño)

**Contexto:** MCode reserva `create_goal` al cliente/usuario; la extensión ACP de la TUI soporta crear Goals pero exige sesión y cliente propios.

**Decisión:** core determinista funcional + ACP adapter estrecho + journal atómico + planificador de candidaturas con evidencia. Usar un único proceso `mcode acp`, estado fuera de los repositorios y `get` antes de mutar. Notificaciones son hints; `get` es verdad.

**Descartado:** leer/editar SQLite interno; emular `/goal` con texto en la TUI; hook `Stop` recursivo; lanzar un `mcode exec` por Goal; MCP o HTTP server solo para orquestar el ciclo.

**Consecuencias:** MVP nativo requiere comprobación E2E ACP y handling de reconexión. Una Skill instalada en TUI abierta **no controla** automáticamente su Session; no afirmar lo contrario. Mantener un solo writer y fail-closed ante límites del host.
